# What is in this folder

This is **not a source project**. It is a downloaded production build of Inside Hoi An
with fixes applied directly to the compiled output, plus a small local server to run it.
There is no React/TypeScript source here, which is why every fix is described as a patch
to `dist/` rather than a code change.

## Run it

```
serve.bat                 # or: python serve.py 4173
```

Then open <http://127.0.0.1:4173>. `serve.py` needs nothing but Python 3.

The `README.md` in this folder is the original Google AI Studio boilerplate and tells you
to run `npm install && npm run dev`. **That cannot work here** — there is no source for
Vite to build. It is kept because it points at the upstream AI Studio project, which is
where real source changes belong.

## Layout

```
dist/                     the app. this is the web root serve.py hands out
  index.html              shell + every CSS fix, numbered and commented (rules 1-40)
  sw.js                   service worker: offline shell, media and map-tile caching
  manifest.webmanifest    PWA manifest
  assets/                 the compiled bundle, stylesheet, and 9 bundled photos
  images/                 17 photos referenced by the app
  brand/  icons/          logo art, favicons, PWA icons, payment marks
  screenshots/            PWA install-prompt screenshots
  _api/                   captured API responses, replayed by serve.py for /api/*

tools/                    the four scripts that reproduce the performance pass
serve.py  serve.bat       local server: gzip, WebP negotiation, SPA routing, /api replay
BUG-AUDIT.md              the full audit: every defect found, fixed, or deferred
STRUCTURE.md              this file
InsideHoiAnLogo.png       source art the brand assets were generated from
.original-backup/         recovery copies - see its own README

package.json, vite.config.ts, tsconfig.json, metadata.json, .env.local, .gitignore
                          the AI Studio scaffold. inert here; kept for the upstream project
```

## Two things that will surprise you

**Image files have twins.** Every photo in `images/` and `assets/` has up to three
companions generated by `tools/`:

| file | what it is |
|---|---|
| `photo.jpg` | the image, re-encoded |
| `photo.webp` | same image, WebP. `serve.py` serves it under the `.jpg` URL when the browser accepts it |
| `photo-160.jpg` | 160px version for the 88 map markers (40x40) and avatar slots |
| `photo-160.webp` | the same, in WebP |

That is why `dist/images/` holds 68 files for 17 photos. Deleting the twins does not
break the app — it just makes it slow again, and `tools/` regenerates them.

**Fixes live in the compiled bundle.** `dist/assets/index-B97Xc7BA.js` has been patched
in place. Anything rebuilt from the real source loses every fix in `BUG-AUDIT.md`. The
fixes are all documented there so they can be reapplied upstream, and `tools/` re-runs
the performance ones mechanically.

## Where things are written down

- `BUG-AUDIT.md` — the audit. Defects 1-19, visual polish 20-33, brand/PWA, payment
  marks, and the performance pass 35-40, each with what was measured and what changed.
- `tools/README.md` — what each script does and the order to run them in.
- `.original-backup/README.md` — what each backup is and how to restore from it.
- `dist/index.html` — every CSS rule is numbered and carries the reason it exists.
